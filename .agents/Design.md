# Design System Inspired by Gumloop

## 1. Visual Theme & Atmosphere

Gumloop's design system embodies a modern, tech-forward aesthetic built for enterprise-grade AI infrastructure. The visual language combines clean minimalism with purposeful depth, using a carefully selected palette of brand purples and accent blues alongside high-contrast neutrals. The system prioritizes clarity and accessibility, with generous whitespace and systematic spacing that guides users through complex agent-building workflows. Subtle color accents and thoughtful elevation create distinction between interactive layers without visual noise. The overall mood is professional yet approachable—sophisticated enough for technical users, but inviting enough for business teams new to AI automation.

**Key Characteristics**
- Clean, minimal aesthetic with enterprise credibility
- High contrast between text and background for accessibility
- Systematic use of color to signal function and hierarchy
- Generous whitespace and breathing room in layouts
- Purposeful elevation through color and shadow, not complexity
- Modern sans-serif typography with consistent rhythm
- Pill-shaped buttons and soft interactive elements contrast with sharp containers
- Decorative color accents used sparingly for visual interest

### Primary
- **Primary / Brand** (`{colors.primary}` — `#5B5FC7`): Primary call-to-action buttons, brand accent elements, active states, and hero highlights. Used prominently in landing page CTAs and interactive controls.

## 5. Layout Principles

### Spacing System
Base unit: `4px` — all spacing values are multiples of 4px for consistent rhythm.

**Spacing Scale**
- `{spacing.xxs}` = `4px` — Tight padding on small components; minimal gaps
- `{spacing.xs}` = `8px` — Button padding; tight form spacing
- `{spacing.sm}` = `12px` — Component internal spacing; small gaps
- `{spacing.md}` = `16px` — Standard padding; medium gaps
- `{spacing.lg}` = `20px` — Larger component padding; section internal spacing
- `{spacing.xl}` = `24px` — Large internal padding; strong separation
- `{spacing.xxl}` = `28px` — Extra-large padding; major content separation
- `{spacing.xxxl}` = `32px` — Maximum internal padding; hero sections
- `{spacing.section}` = `36px` — Section-level spacing; between major blocks
- `{spacing.band}` = `40px` — Band/section padding; full-width containers

### Grid & Container
- Maximum content width: Approximately `992px` at 1024px viewport; `449px` at 1440px viewport (narrow content columns suggest card-based layout)
- Column count: Consistently `5` columns across all measured breakpoints
- Navigation and footer span full viewport width (`1440px` measured)
- Section padding (horizontal): `0px` across all breakpoints; full-bleed sections with internal gutters

### Whitespace Philosophy
The system emphasizes breathing room over density. Sections are separated by substantial vertical gaps (`{spacing.section}` and `{spacing.band}`), allowing visual rest. Card-based layouts use uniform `{spacing.md}` to `{spacing.lg}` internal padding. Text in body copy maintains `{spacing.md}` line-height multiplier (1.5×) for readability.

### Border Radius Scale
- `{rounded.none}` = `0px` — Images, cards (when sharp), overlays, modals
- `{rounded.xs}` = `2px` — Subtle rounding on minimal elements
- `{rounded.sm}` = `4px` — Light rounding; small components
- `{rounded.md}` = `6px` — Standard rounding; form fields
- `{rounded.lg}` = `8px` — Button radius (primary variant); card radius; common interactive element radius
- `{rounded.xl}` = `10px` — Slightly larger rounding; emphasis elements
- `{rounded.full}` = `9999px` — Pill-shaped buttons, badges, and circular icon buttons

## 6. Depth & Elevation

| Level | Treatment | Use |
|---|---|---|
| Flat | No shadow | Default cards, backgrounds, text-only sections |
| Hover Lift | `rgba(0, 0, 0, 0.1) 0px 1px 3px 0px, rgba(0, 0, 0, 0.1) 0px 1px 2px -1px` | Icon button, subtle interactive lift |
| Layered Micro | `rgba(0, 0, 0, 0.016) 0px 1px 1px -0.5px, rgba(0, 0, 0, 0.016) 0px 3px 3px -1.5px, rgba(0, 0, 0, 0.01) 0px 6px 6px -3px, rgba(0, 0, 0, 0.01) 0px 12px 12px -6px, rgba(0, 0, 0, 0.01) 0px 24px 24px -12px` | Text Large buttons, elevated interactive elements |

**Shadow Philosophy**
The system employs a color-blocking and subtle shadow approach. Most containers are flat with no shadow, relying on border color and background tint for distinction. Interactive elements (buttons, hover states) receive minimal shadows to signal affordance without visual heaviness. Shadows use low-opacity black (`0.01–0.1`) to maintain sophistication. The layered-micro approach on larger buttons simulates gentle elevation through multiple, near-transparent layers rather than a single heavy shadow.

### Opacity Levels
The system uses opacity to control visibility and state:
- `10%` (`0.1`) — Very subtle background tints; disabled overlay on surfaces
- `8%` (`0.08`) — Minimal opacity for decorative elements
- `12%` (`0.12`) — Light opacity for secondary states
- `30%` (`0.3`) — Medium opacity; semi-transparent backgrounds in gradients
- `45%` (`0.45`) — Button background transparency; moderate tint
- `65%` (`0.65`) — Focus/hover state overlays
- `68%` (`0.68`) — Input focus state backgrounds

### Z-index / Layering
The stacking order supports depth hierarchy:
- `z-index: 1` — Base layer; default content
- `z-index: 2` — Raised content; cards above background
- `z-index: 3` — Elevated interactive; inputs above cards
- `z-index: 4` — Overlay; modal underlay or dropdown shadow
- `z-index: 7` — Dropdown menus and popovers
- `z-index: 8` — Sticky headers and fixed elements
- `z-index: 9` — Top-level overlays; notification toasts
- `z-index: 10` — Maximum; true modals and full-screen overlays

## 7. Do's and Don'ts

### Do
- Use `{colors.primary}` (`#5B5FC7`) for primary call-to-action buttons and brand-critical interactions
- Apply `{spacing.md}` (`16px`) as the default internal padding for components; scale up or down as needed
- Maintain `{rounded.lg}` (`8px`) as the default radius for interactive buttons and cards
- Use pill-shaped buttons (`{rounded.full}` — `9999px`) only for icon buttons and badges
- Align all spacing to the 4px grid; all margins and padding must be multiples of 4px
- Employ subtle shadows from the layered-micro palette for depth on important interactive elements
- Build layouts with generous whitespace; avoid cramped, text-dense designs
- Use high contrast (black or near-black text on white or light backgrounds) for accessibility
- Apply opacity sparingly for hover and disabled states (8–12% for subtle effects, 30–45% for moderate effects)
- Implement focus states with outline or border changes; avoid relying on color alone
- Implement proper pagination and debounce

### Don't
- Do not use decorative accent colors (`{colors.accent-1}` through `{colors.accent-6}`) for functional states (error, success, warning); they are visual ornaments only
- Do not apply sharp corners (`{rounded.none}`) to interactive buttons; maintain `{rounded.lg}` minimum
- Do not stack heavy shadows; rely on color blocking and minimal opacity instead
- Do not use spacing values outside the established scale; always default to multiples of `{spacing.md}` (`16px`)
- Do not mix font families within a single component (e.g., heading + body text in one card)
- Do not use text smaller than `12px` (Heading S / Caption size); maintain readability
- Do not overcrowd sections; maintain `{spacing.band}` (`40px`) minimum vertical gap between major sections
- Do not apply rounded corners to image containers; keep them sharp (`{rounded.none}`)
- Do not use focus rings or outlines thinner than `2px`; accessibility requires clear focus indicators
- Do not apply opacity to text colors directly; use background opacity instead for semantic clarity
