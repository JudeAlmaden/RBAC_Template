# Template Identity — Read This First

This repository is **`RBAC_Template`, a reusable starter kit** (Laravel + Inertia + React with multi-role RBAC/PBAC), **not a deployed product and not anyone's live application**. Brand name is the placeholder `Template`. It exists to be copied into new projects.

Do not assume otherwise. Specifically:

- The seeded accounts (`superadmin@example.com`, `admin@example.com`, `user@example.com`, password `password`) are fixtures, not real users. Never treat them as production accounts.
- `CHANGELOG.md`, the `package.json` version (`1.2.x`) and the git history describe the **template's own evolution**. They are not the release history or roadmap of whatever app is being built here.
- The README feature list is a description of what the kit ships with, not a requirements document. The Welcome page, Dashboard cards and demo data are showcase content, not product requirements.
- Optional subsystems (notification centre, audit log, role switcher, activity history tabs) are available infrastructure. Ask before assuming a new project needs them.
- Do not deploy, publish or point this repo at real infrastructure unless the user explicitly asks.

## If the user is working on a new project built from this template

Run this bootstrap before feature work, and say what you changed:

1. **Identity** — set `APP_NAME` in `.env` (keep `VITE_APP_NAME="${APP_NAME}"`), replace the hardcoded `"Template"` brand string in `resources/js/Layouts/AuthenticatedLayout.jsx`, the logo in `resources/js/Components/ApplicationLogo.jsx`, the browser title, and the copy on `resources/js/Pages/Welcome.jsx`.
2. **Data** — `php artisan migrate:fresh --seed` after editing `database/seeders/DatabaseSeeder.php` to create only the project's real roles/accounts; delete leftover `activity_logs`/`notifications` demo rows.
3. **Versioning** — reset `package.json` to `0.1.0` and open a fresh `CHANGELOG.md` entry for the new project; truncate `.agents/RECENT_CHANGES.md`.
4. **History** — a new project should start its own repository (or a squashed initial commit) instead of inheriting the template's commits and tags.
5. **Docs** — the template docs under `.agents/Documentation/` (`RBAC-PBAC.md`, `NOTIFICATIONS.md`, `EXTENDING.md`) stay useful; anything project-specific belongs in the new project's own files.

When scope is ambiguous, ask which project is being worked on rather than assuming this repo is the product. Keep changes scoped to what was requested; do not "finish" a template subsystem the user did not ask about.

## Commit & Versioning Workflow

When the user asks to "make a commit", "version this", or "commit changes", follow this sequence.

### 1. Read `.agents/RECENT_CHANGES.md`
It is the AI scratch pad across sessions (git-ignored). It describes everything changed since the
last commit.

### 2. Bump the `package.json` version (semver)
- **Patch** (`x.x.X`): bug fixes, lint fixes, minor tweaks
- **Minor** (`x.X.0`): new features, UI overhauls, removed subsystems ← most common
- **Major** (`X.0.0`): breaking schema/API changes

### 3. Prepend a `CHANGELOG.md` entry
Use the existing format exactly:

```
## [X.Y.Z] - YYYY-MM-DD

### Added
- ...

### Changed
- ...

### Removed
- ...

### Fixed
- ...

### Technical
- Modified: <key files>
- New: <new files>
- Deleted: <deleted files>
- Tests: <test count> passing — lint/typecheck clean
```

Source the details from `.agents/RECENT_CHANGES.md`.

### 4. Keep `.agents/RECENT_CHANGES.md` out of the commit
It is listed in `.gitignore` under `# AI assistant artifacts`. Never commit it.

### 5. Stage and commit
```
git add -A
git commit -m "feat: <short summary> (v<X.Y.Z>)"
```
Conventional prefixes only: `feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`.

### Maintaining `.agents/RECENT_CHANGES.md`
- Update it continuously while working.
- Organise by numbered feature/fix sections.
- After a commit, truncate it to cover only post-commit changes.

### Before committing
- Run `vendor/bin/pint --dirty --format agent` if PHP changed.
- Run `npm run lint` and the relevant `php artisan test --compact` scope; both must pass.
- Never commit `.env`, `*.db`/`*.sqlite`, `public/build`, `public/hot`, or AI scratch files.
